Meine tmux.conf

Dotfiles Terminal Referenz

Diese Konfiguration wandert seit Jahren von Rechner zu Rechner, und jedes Mal suche ich sie an einem anderen Ort: in einem alten Backup, in einer Chat-Historie, in einem Gist, den ich nicht mehr finde. Ein eigenes Dotfiles-Repo dafür anzulegen wäre Overkill – also liegt sie ab jetzt hier. Vollständig, zum Kopieren, und diesmal mit einer Erklärung zu jedem Block, damit ich in zwei Jahren noch weiß, warum eine Zeile drinsteht.

In drei Schritten einsatzbereit

Konfiguration nach ~/.tmux.conf legen, TPM klonen, Plugins installieren:

curl -o ~/.tmux.conf https://schultet.github.io/assets/tmux.conf
git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm
tmux new -s dev        # Session starten
# darin: Ctrl-a  gefolgt von  I   →  Plugins installieren

Läuft schon eine tmux-Session, genügt danach Ctrl-a r zum Neuladen.

Die vollständige Konfiguration

~/.tmux.conf Download 
# ~/.tmux.conf

# ============================================
# ESSENTIAL SETTINGS
# ============================================

# Fix Vim ESC delay
set -sg escape-time 0

# Increase scrollback buffer
set -g history-limit 50000

# Start windows and panes at 1, not 0
set -g base-index 1
setw -g pane-base-index 1

# Enable mouse support
set -g mouse on

# Enable focus events for vim autoread
set -g focus-events on

# Set terminal with proper colors
set -g default-terminal "tmux-256color"
set -as terminal-features ",xterm-256color:RGB"

# Aggressive resize for multi-client
setw -g aggressive-resize on

# ============================================
# KEY BINDINGS
# ============================================

# Change prefix to Ctrl+a (more ergonomic)
unbind C-b
set -g prefix C-a
bind C-a send-prefix

# Reload config
bind r source-file ~/.tmux.conf \; display "Config reloaded!"

# Better pane splitting (and keep current path)
bind | split-window -h -c "#{pane_current_path}"
bind - split-window -v -c "#{pane_current_path}"
bind c new-window -c "#{pane_current_path}"

# Vim-style pane navigation
bind h select-pane -L
bind j select-pane -D
bind k select-pane -U
bind l select-pane -R

# Vim-style pane resizing
bind -r H resize-pane -L 5
bind -r J resize-pane -D 5
bind -r K resize-pane -U 5
bind -r L resize-pane -R 5

# ============================================
# APPEARANCE
# ============================================

# Status bar position
set -g status-position top

# Status bar colors
set -g status-style 'bg=#13161d fg=#8b949e'
set -g status-left-length 20
set -g status-right-length 50

# Status bar content
set -g status-left '#[fg=#00e68a,bold] #S #[fg=#30363d]│ '
set -g status-right '#[fg=#30363d]│#[fg=#8b949e] %H:%M #[fg=#30363d]│#[fg=#8b949e] %d-%b-%y '

# Window status
setw -g window-status-format ' #I:#W '
setw -g window-status-current-format '#[fg=#00e68a,bold] #I:#W '

# Pane border colors
set -g pane-border-style 'fg=#30363d'
set -g pane-active-border-style 'fg=#00e68a'

# Message styling
set -g message-style 'bg=#00e68a fg=#000000 bold'

# ============================================
# COPY MODE
# ============================================

# Use vi keys
setw -g mode-keys vi

# Vi-style copy bindings
bind -T copy-mode-vi v send -X begin-selection
bind -T copy-mode-vi y send -X copy-pipe-and-cancel "pbcopy"  # macOS
# bind -T copy-mode-vi y send -X copy-pipe-and-cancel "xclip -selection clipboard -i"  # Linux


# Smart pane switching with awareness of Vim splits
is_vim="ps -o state= -o comm= -t '#{pane_tty}' \
    | grep -iqE '^[^TXZ ]+ +(\\S+\\/)?g?(view|l?n?vim?x?|fzf)(diff)?$'"
bind-key -n 'C-h' if-shell "$is_vim" 'send-keys C-h' 'select-pane -L'
bind-key -n 'C-j' if-shell "$is_vim" 'send-keys C-j' 'select-pane -D'
bind-key -n 'C-k' if-shell "$is_vim" 'send-keys C-k' 'select-pane -U'
bind-key -n 'C-l' if-shell "$is_vim" 'send-keys C-l' 'select-pane -R'

bind-key -T copy-mode-vi 'C-h' select-pane -L
bind-key -T copy-mode-vi 'C-j' select-pane -D
bind-key -T copy-mode-vi 'C-k' select-pane -U
bind-key -T copy-mode-vi 'C-l' select-pane -R

# ============================================
# PLUGINS (via TPM)
# ============================================

# Install TPM first:
# git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm

set -g @plugin 'tmux-plugins/tpm'
set -g @plugin 'tmux-plugins/tmux-sensible'
set -g @plugin 'tmux-plugins/tmux-resurrect'
set -g @plugin 'tmux-plugins/tmux-continuum'

# Plugin settings
set -g @resurrect-strategy-vim 'session'
set -g @continuum-restore 'on'

# Initialize TPM (keep at bottom)
run '~/.tmux/plugins/tpm/tpm'

Die Rohdatei liegt unter assets/tmux.conf – direkt curl-bar, falls ich sie mal auf einem frischen Server brauche.

Was hier warum drinsteht

Grundeinstellungen

escape-time 0 ist die wichtigste Zeile der ganzen Datei, wenn man Vim benutzt. tmux wartet standardmäßig einen Moment nach einem ESC, um zu prüfen, ob eine Escape-Sequenz folgt. In Vim fühlt sich das an, als hänge der Wechsel in den Normal-Modus. Auf 0 gesetzt ist der Effekt sofort weg. Das -s ist dabei kein Tippfehler: Es ist eine Server-Option, keine Session-Option.

history-limit 50000 gilt nur für neu erzeugte Panes – bestehende behalten ihren alten Puffer, auch nach einem Reload. Wer das gerade erst gesetzt hat und sich wundert: Pane einmal neu öffnen.

base-index 1 und pane-base-index 1 verschieben die Nummerierung von Fenstern und Panes auf 1, damit sie zur Tastaturreihe passt. Ctrl-a 1 ist das erste Fenster, nicht das zweite. Klingt nach einer Kleinigkeit, spart aber jeden Tag ein paar Fehlgriffe.

default-terminal und terminal-features sorgen für echte 24-Bit-Farben. tmux-256color ist das korrekte terminfo für tmux ≥ 2.9; die zweite Zeile sagt tmux, dass das äußere Terminal (hier xterm-256color) RGB kann. Die Option terminal-features gibt es erst ab tmux 3.2 – auf älteren Versionen lautet das Äquivalent set -ga terminal-overrides ",xterm-256color:Tc".

aggressive-resize on ist nur relevant, wenn mehrere Clients an derselben Session hängen: Ohne die Option richtet sich ein Fenster nach dem kleinsten verbundenen Client, mit ihr nur nach dem kleinsten, der dieses Fenster gerade auch wirklich anzeigt. Wer per tmux attach von zwei verschieden großen Terminals aus arbeitet, merkt den Unterschied sofort.

Stolperfalle: fehlendes terminfo

Auf älteren macOS-Installationen fehlt der Eintrag tmux-256color in der Systemdatenbank, und tmux startet dann mit einer Fehlermeldung oder kaputten Farben. Prüfen lässt sich das mit infocmp tmux-256color. Fehlt er, hilft ein aktuelles ncurses (brew install ncurses) oder ersatzweise screen-256color als default-terminal.

Prefix auf Ctrl-a

Der Standard-Prefix Ctrl-b verlangt eine unbequeme Handhaltung. Ctrl-a liegt direkt neben der Home-Row und ist der Klassiker aus GNU screen. Der Preis: In der Shell ist Ctrl-a normalerweise „an den Zeilenanfang springen“. Genau dafür steht bind C-a send-prefix in der Datei – zweimal Ctrl-a schickt das Zeichen an die darunterliegende Anwendung durch. Nach kurzer Eingewöhnung tippt man das automatisch.

Splits, die den Pfad behalten

| und - sind als Split-Tasten schlicht deshalb besser als % und ", weil sie aussehen wie das, was sie tun. Wichtiger ist aber das -c "#{pane_current_path}" an jedem Split und am neuen Fenster: Ohne das startet jedes neue Pane im Verzeichnis, aus dem die Session gestartet wurde – praktisch immer das falsche. Mit dem Zusatz öffnet sich das neue Pane dort, wo man gerade steht.

Navigation: zweimal dasselbe, mit Absicht

Es gibt hier zwei Wege, das Pane zu wechseln, und das ist kein Versehen:

  • Mit Prefix (Ctrl-a h/j/k/l) – funktioniert immer, auch wenn ein Programm im Pane die Strg-Tasten selbst belegt.
  • Ohne Prefix (Ctrl-h/j/k/l) – der schnelle Weg, dank -n ohne Prefix gebunden.

Der Trick beim zweiten Weg ist die is_vim-Abfrage: Sie schaut per ps nach, welches Programm im Ziel-Pane läuft. Ist es Vim, Neovim oder fzf, wird der Tastendruck durchgereicht, sodass Vim seine eigenen Fenster wechselt; ist es etwas anderes, wechselt tmux das Pane. Ergebnis: eine einzige Tastenkombination bewegt den Cursor nahtlos über Vim-Splits und tmux-Panes hinweg, ohne dass man wissen muss, wo gerade die Grenze verläuft.

Die großgeschriebenen Varianten H/J/K/L ändern die Größe. Ihr -r macht sie wiederholbar: Nach einmal Ctrl-a genügt mehrfaches L, um weiter zu vergrößern – innerhalb des Zeitfensters von repeat-time (Standard: 500 ms).

Stolperfalle: Ctrl-l löscht nicht mehr den Bildschirm

Weil Ctrl-l jetzt global von tmux abgefangen wird, kommt es nicht mehr in der Shell an. Wer die Gewohnheit behalten will, bindet den Bildschirm-Reset hinter den Prefix:

bind C-l send-keys 'C-l'

Copy-Mode

mode-keys vi schaltet den Scroll- und Auswahlmodus auf Vim-Tasten um: Ctrl-a [ startet ihn, danach navigiert man mit h/j/k/l, / sucht, v beginnt die Auswahl und y kopiert und verlässt den Modus.

Die y-Bindung reicht die Auswahl an die Systemzwischenablage weiter – und das ist die eine Zeile, die man beim Umzug auf ein anderes System anpassen muss. Aktiv ist die macOS-Variante mit pbcopy; darunter steht die Linux-Variante mit xclip auskommentiert bereit. Unter Wayland lautet sie entsprechend:

bind -T copy-mode-vi y send -X copy-pipe-and-cancel "wl-copy"

Statuszeile

Die Statuszeile sitzt oben (status-position top), weil unten meist schon die Prompt-Zeile Aufmerksamkeit beansprucht. Links steht der Session-Name, rechts Uhrzeit und Datum, dazwischen die Fenster – das aktive in Grün (#00e68a). Dieselbe Farbe markiert den Rahmen des aktiven Panes, was bei drei oder mehr Panes das schnellste Erkennungsmerkmal ist. Die #[fg=...]-Ausdrücke sind tmux-eigene Formatanweisungen, keine Kommentare – das # hat hier eine andere Bedeutung als am Zeilenanfang.

Plugins

Vier Plugins, verwaltet vom Tmux Plugin Manager:

  • tmux-sensible – eine Sammlung unstrittiger Grundeinstellungen. Sie überschreibt nichts, was man selbst gesetzt hat, kollidiert also nicht mit den Zeilen weiter oben.
  • tmux-resurrect – speichert und restauriert die komplette Session-Struktur (Fenster, Panes, Layouts, Arbeitsverzeichnisse) über Neustarts hinweg.
  • tmux-continuum – automatisiert das: sichert im Hintergrund alle 15 Minuten und stellt dank @continuum-restore 'on' beim Start des tmux-Servers automatisch wieder her.

Die Zeile run '~/.tmux/plugins/tpm/tpm' muss die letzte der Datei bleiben – TPM überschreibt sonst Einstellungen, die danach kommen.

Wichtig: Diese fünf Zeilen installieren nichts. Sie notieren nur, was installiert werden soll. Ohne den Schritt aus dem nächsten Abschnitt passiert genau gar nichts – und zwar ohne jede Fehlermeldung.

Plugins zum Laufen bringen

Das ist die Stelle, an der diese Konfiguration am leisesten scheitert. Fehlt ~/.tmux/plugins/tpm, schlägt die letzte Zeile fehl – aber run bricht das Einlesen der Konfiguration nicht ab, und weil sie ohnehin die letzte ist, geht auch nichts verloren. tmux startet normal, alle eigenen Bindungen funktionieren, nur die vier Plugins sind stumm. Man kann das jahrelang übersehen.

Zuerst: laufen sie überhaupt?

Drei Kommandos, die das ohne Zweifel klären:

ls ~/.tmux/plugins/                        # liegt TPM da?
tmux list-keys -T prefix | grep -E ' (I|U) '   # hat TPM seine Tasten gebunden?
tmux show -g status-interval               # 15 = tmux-Standard, 5 = sensible aktiv
So liest man das Ergebnis
BefundBedeutung
No such file or directoryTPM ist nicht geklont – kein Plugin lief je
keine Treffer bei I/UTPM wurde nie ausgeführt
status-interval 15tmux-Standardwert – tmux-sensible hätte hier 5 gesetzt
status-interval 5tmux-sensible ist aktiv, TPM läuft
Achtung, irreführend

tmux show -g zeigt auch ohne installierte Plugins brav @continuum-restore on und @resurrect-strategy-vim session an. Das sieht nach einem Lebenszeichen aus, ist aber keins: @-Optionen sind bloße Benutzeroptionen, die die Konfigurationsdatei selbst setzt. Sie beweisen nur, dass die Datei gelesen wurde – nicht, dass irgendein Plugin existiert.

Dasselbe gilt für @plugin: Alle vier Zeilen schreiben in dieselbe Option, es überlebt also nur die letzte. TPM stört das nicht, weil es die Konfigurationsdatei als Text durchsucht statt Optionen zu lesen.

Installieren

TPM klonen, Konfiguration neu einlesen, Plugins holen:

git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm
tmux source-file ~/.tmux.conf

Dann in einer laufenden tmux-Session Ctrl-a gefolgt von I drücken – großes I, also mit Shift. Der Bildschirm friert kurz ein, während TPM die Repositories klont; danach meldet er „Done, press ESC to continue“. Auf einem frischen Rechner ohne interaktiven Schritt geht es auch direkt:

~/.tmux/plugins/tpm/bin/install_plugins

Danach sollten vier Ordner dastehen:

$ ls ~/.tmux/plugins/
tmux-continuum  tmux-resurrect  tmux-sensible  tpm

Was man dann hat

Tasten, die erst nach der Installation existieren
TasteWirkung
C-a IPlugins aus der Konfiguration installieren
C-a UInstallierte Plugins aktualisieren
C-a M-uPlugins entfernen, die nicht mehr in der Konfiguration stehen
C-a C-sSession-Struktur jetzt sichern (resurrect)
C-a C-rZuletzt gesicherten Stand wiederherstellen

Gesichert wird nach ~/.local/share/tmux/resurrect/ (ältere Versionen: ~/.tmux/resurrect/) – eine Textdatei pro Snapshot, die man auch von Hand ansehen kann.

Wenn es nicht klappt

C-a I tut nichts. Entweder ist TPM nicht geklont, oder die Konfiguration wurde nach dem Klonen nicht neu eingelesen, oder run '~/.tmux/plugins/tpm/tpm' ist nicht die letzte Zeile der Datei.

continuum stellt nichts wieder her. @continuum-restore 'on' greift nur, wenn der tmux-Server frisch startet – nicht beim attach an eine bereits laufende Session. Ob überhaupt schon gesichert wurde, verrät tmux show -g @continuum-save-last-timestamp; ist die Option leer, gab es noch keinen Speicherlauf.

Nach dem Restore ist Vim leer. Dafür fehlt vim-obsession – siehe unten.

Detail zu resurrect-strategy-vim

@resurrect-strategy-vim 'session' stellt offene Vim-Instanzen samt geöffneter Dateien wieder her – setzt aber voraus, dass in Vim das Plugin vim-obsession installiert ist und eine Session-Datei schreibt. Ohne das startet Vim nach dem Restore einfach leer.

Oder eben bleiben lassen

Die Plugins sind Komfort, kein Fundament. Wer sie nicht will, löscht die vier @plugin-Zeilen, die beiden @-Einstellungen darunter und die run-Zeile am Ende – alles andere in dieser Konfiguration funktioniert unverändert weiter, weil es reines tmux ist. Das ist eine völlig legitime Variante, und sie hat den Vorteil, dass die Datei dann ohne jede externe Abhängigkeit auf jedem Rechner sofort tut, was sie soll.

Herkunft

Das meiste hiervon ist über die Jahre aus Foren, Blogposts und fremden Dotfiles zusammengewachsen; die einzelnen Optionen sind Standard-tmux und gehören niemandem. Eine Ausnahme ist der Block mit der is_vim-Abfrage: Der stammt erkennbar aus christoomey/vim-tmux-navigator und steht dort unter der MIT-Lizenz – verwendbar, aber mit Namensnennung. Deshalb steht sie hier. TPM und die drei Plugins von tmux-plugins sind ebenfalls MIT-lizenziert und werden ohnehin separat geklont, nicht kopiert.
